# Community status: Surface Pro X (SQ1/SQ2, sc8180x) on Linux

Compiled 2026-11-11 by the community-status agent, using web fetch and search only. Nothing was downloaded, built or posted.
Each claim lists its source and the date of the evidence. **[unverified]** means the claim could not be confirmed from a primary source.

Caveats on sources:
- lore.kernel.org, patchwork.kernel.org, gitlab.freedesktop.org and the OFTC IRC logs refused automated fetches (HTTP 403 or Anubis). Mailing-list evidence therefore comes from mirrors (ratatoskr.run, lkml.iu.edu, mail-archive.com). Merge state was checked against `torvalds/linux` master, which was **v7.4-rc2** on 2026-11-11 ([Makefile](https://raw.githubusercontent.com/torvalds/linux/master/Makefile)).
- linux-next and the maintainer `for-next` trees (qcom, hid) were **not** checked. Anything that may be queued for 7.5 is marked "not in master".

## TL;DR

- **Most current out-of-tree base:** linux-surface/kernel `spx/v7.3` (Linux **7.3.1**, rebased 2026-11-01 by Maximilian Luz / qzed), plus `spx/v7.3-dev`, which is 19 commits ahead. `spx/v7.3-dev` swaps in the upstream-candidate spi-hid driver and adds Surface Pro X draft-protocol support.
- **Upstreaming has started, but no Pro X DTS is upstream yet.** On 2026-11-03, Val Packett (valpackett) published a cleaned-up DTS split: `sc8180x-microsoft-surface-pro-x.dtsi` plus `-cambria` (SQ1 LTE), `-caspar` (SQ1 Wi-Fi) and `-carina` (SQ2) `.dts` files. qzed agreed to add his Signed-off-by. As of 2026-11-11 I found no list posting **[unverified: lore was not reachable]**.
- **This project's device (SQ1, SKU 1876) has never been the primary test target.** The linux-surface DTS is SQ2-only: model "Microsoft Surface Pro X (SQ2)", SQ2 CPU OPPs, firmware under `qcom/msft/surface/pro-x-sq2/`. Val's split is the first to give SQ1 its own file. An SQ1 owner who can test is the most useful thing we can bring.

## Distro efforts

- **Arch Linux ARM via linux-surface:** this is the only supported route. Use the `aarch64-arch-mkimg` patched installer plus the aarch64-packages repo ([Basic Setup](https://github.com/linux-surface/surface-pro-x/wiki/Basic-Setup)). Community "v0.1.6" images are unmaintained, per Val in #51 (2026-10-03).
- **Ubuntu 26.10 "Snapdragon concept" ISOs** (Linux 7.3) cover X1/X2 laptops only. No sc8180x ([Phoronix](https://www.phoronix.com/news/Ubuntu-26.10-Snapdragon-Concept)).
- **Fedora 44/45:** automatic DTB selection for WoA laptops (Hans de Goede, now at Qualcomm). The focus is X1. Nothing for sc8180x ([Phoronix F44](https://phoronix.com/news/fedora-44-approves-dtb-woa), [Fedora WoA wiki](https://fedoraproject.org/wiki/Snapdragon_WoA_Laptop_Install)). Fedora's DTB auto-selection needs an upstream DTB, so it only becomes relevant to us once the Pro X DTS lands. An old Fedora request is [#44](https://github.com/linux-surface/surface-pro-x/issues/44).
- **postmarketOS:** has `soc-qcom-sc8180x` / `linux-postmarketos-qcom-sc8180x` packages for the Flex 5G, which is where the audio DT bits came from. No Pro X device port found **[unverified]**.
- **denysvitali** says (2026-11-03) he will publish a mainline kernel plus scripts with cameras, GPS, speakers and alt-mode working ([#7](https://github.com/linux-surface/surface-pro-x/issues/7), [post](https://x.com/DenysVitali/status/2093443438230299015)). His public repos show no matching code yet **[unverified]**. His older `denysvitali/surface-pro-x-linux` (spx-5.16) is obsolete.

## Best starting point (recommendation)

1. **Kernel base:** use **linux-surface/kernel `spx/v7.3-dev`** (7.3.1, 2026-11-01). It is the newest tree known to work on the device, and it already carries the upstream-track spi-hid stack. Fall back to `spx/v7.3` if the new spi-hid misbehaves. For upstream work, rebase onto mainline v7.4-rc / linux-next, because the clk fixes and part of the PCIe/USB rework are already there.
2. **DTS:** use **Val Packett's `sc8180x-microsoft-surface-pro-x.dtsi` + `sc8180x-microsoft-cambria.dts`** ([b2359e3](https://github.com/valpackett/linux-qclaptops/commit/b2359e3e5743206f499e53b8eff9cfd05590cb81)) for our SQ1 (cellular). Port in the spx-only extras as follow-up patches: touchscreen spi-hid node, PMIC ADC/thermal, ALS. Do **not** draft a new DTS from the Flex 5G base as PLAN.md wave 2 currently says, because that would duplicate Val's work. Coordinate with Val before posting anything.
3. **Firmware layout:** match Val's paths `qcom/sc8180x/microsoft/cambria/*.mbn` (these are what will go upstream), not spx's `qcom/msft/surface/pro-x-sq2/`. Use `aarch64-firmware/scripts/getfw.py` only as a reference for our own `extract-firmware.ps1`; it is dormant since 2022.
4. **Verify SKU first:** confirm from the hw-capture SMBIOS/ACPI data that SKU 1876 is SQ1 with LTE (cambria) and not the Wi-Fi-only caspar. **[unverified mapping]**
